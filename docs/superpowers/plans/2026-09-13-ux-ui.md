# Plan de mejora UX/UI — Panel UD Santiso

Fecha: 13/09/2026. Estado: propuesto; implementación no iniciada.

**Objetivo:** gestionar competición y producir carteles con contexto claro, guardados fiables y uso completo en móvil.

**Base:** [auditoría por pestaña](../../audits/2026-09-13-ux-ui.md). Referencia de código: `7a6c94f`.

**Enfoque:** conservar identidad negro/amarillo y capacidades existentes. Corregir primero integridad y navegación; aplicar después patrones comunes y simplificaciones por pantalla. Reutilizar `components/ui/AdminUI.tsx` y dividir componentes grandes solo donde facilite cambios concretos.

**Tecnología:** Next.js 16.2.4, React 19.2.4, TypeScript, CSS y Supabase. Usar exclusivamente pnpm. Antes de implementar leer guías pertinentes en `node_modules/next/dist/docs/`; comprobar esquema/RPC real antes de diseñar migraciones.

## Orden de entrega

1. **Fase A — Fiabilidad:** tareas 1–3. Corregir contexto inválido, guardados y reemplazo de actas.
2. **Fase B — Base UX:** tareas 4–6. Componentes accesibles, móvil y ajustes alcanzables.
3. **Fase C — Operación diaria:** tareas 7–10. Temporadas, clasificación, equipos, plantilla y patrocinadores.
4. **Fase D — Producción:** tareas 11–13. Carteles, sus siete plantillas e importaciones.
5. **Fase E — Validación:** tarea 14, ejecutada por entrega y al cerrar conjunto.

Dependencias: 4 precede a nuevos formularios/modales; 1 precede a enlaces entre tareas; 3 precede a guardado desde nuevo lote; 6 precede a conectar patrocinadores con composición. Trabajo visual puede prepararse mientras se verifica persistencia, pero no ocultar fallos funcionales con cambios cosméticos.

Tamaño orientativo por tarea: **S** hasta una jornada, **M** 2–3 jornadas, **L** 4–6 jornadas de desarrollo y revisión. No son compromisos de calendario; tareas de datos dependen del esquema remoto. Reestimar tras fase A. No sumar rangos como presupuesto cerrado.

- [ ] Reflejar vista, plantilla y filtros en URL usando API compatible con versión instalada.

## 3. Proteger activación y reemplazo de actas — P1 · L

Archivos: `lib/actas/save-acta.ts`, `components/admin/AdminTemporadas.tsx`, `AdminJornadas.tsx`, `AdminActaImporter.tsx`, `AdminActaBatch.tsx`; migración a definir tras inspección del esquema.

- [ ] Inspeccionar RPC `save_reviewed_acta`, restricciones y relaciones reales.
- [ ] Retirar borrado previo a RPC del cliente. Encapsular reemplazo completo en una transacción; no usar alternativa destructiva parcial si RPC falta.
- [ ] Hacer activación de temporada una operación atómica con error recuperable.
- [ ] Antes de reemplazar acta, presentar destino y cambios; lote analiza primero y guarda solo selección revisada.
- [ ] Matching ambiguo requiere selección manual; filtrar por temporada/categoría/competición y jornada antes de comparar nombres.

Aceptación: en entorno de prueba, fallo inducido al insertar eventos deja acta anterior completa. RPC ausente no borra datos. Dos activaciones concurrentes no producen cero o varias temporadas activas. Actas de competiciones distintas con mismo número de jornada no se asignan automáticamente sin desambiguación.

**Cierre mínimo:** contexto deportivo siempre válido; cero éxitos falsos en fallos simulados; reemplazo de acta atómico; filtros móviles legibles; ajustes localizables; edición sin pérdida silenciosa; siete exportaciones coherentes con preview.

## Fuera de primera entrega

No añadir por defecto panel de métricas, IA adicional, animaciones decorativas, más temas visuales ni rehacer todo CSS. Funciones posteriores: preferencias de idioma/densidad, archivo de temporadas, historial de cambios y biblioteca de borradores compartida. Decidirlas con uso real tras estabilizar tareas principales.
